1. 프로젝트 개요

웹앱 이름
공공이(002) — 일상에 가까운 공공시설

기획 배경 및 문제 정의
일상생활에서 화장실, 주차장, 휴지통 등 가까운 생활시설이 필요할 때 시설 종류마다 따로 검색해야 하는 불편함이 있다. 시설의 위치를 찾더라도 주소, 운영시간, 요금 등 필요한 이용 정보를 다시 확인해야 하는 경우가 많다.
공공이는 서로 다른 공공데이터를 하나의 지도와 목록으로 통합한 반응형 웹앱이다. 사용자의 현재 위치 또는 직접 지정한 위치를 기준으로 가까운 시설을 찾고, 상세 정보를 확인한 뒤 길찾기로 이어지도록 구현하였다. PC와 모바일에서 각각 화면 크기에 맞는 상세 정보 방식을 제공한다.

핵심 아이디어 한 줄 요약
현재 위치 또는 직접 지정한 위치 주변의 7가지 생활시설을 지도와 거리순 목록으로 탐색하고, 상세 정보 확인과 길찾기까지 연결하는 공공데이터 기반 웹앱이다.

2. 활용할 공공 API·오픈데이터

데이터 출처
시설 정보는 공공데이터포털의 공공 API와 행정안전부가 제공하는 파일데이터를 사용한다. 지도 표시, 주소·장소 검색과 외부 길찾기 연결에는 카카오 지도·로컬 서비스를 활용한다.

⑧ 카카오 지도 및 로컬 서비스
제공기관: 주식회사 카카오
원본: https://apis.map.kakao.com/web/
주소·장소 검색: https://developers.kakao.com/docs/ko/local/dev-guide
활용: 지도 표시, 주소·장소 검색, 카테고리별 클러스터와 길찾기 연결

API 방식 확인
주차장·휴지통·공원·금연구역은 공공데이터포털 REST API를 호출하며 인증키가 필요하다. 화장실·무료와이파이·자전거보관소는 프로젝트에 저장된 CSV 자료를 사용하므로 시설 조회 시 해당 자료의 원본 API를 호출하지 않는다.
CSV는 개발 서버 시작 또는 빌드 시 지역별 JSON으로 전처리하고, 브라우저에서는 조회 위치 주변의 파일만 내려받는다. 공공 API도 주변 지자체 코드로 조회 범위를 제한하며, 최대 4개의 요청을 동시에 처리한다. 실제 호출 허용량은 각 API의 활용 신청 계정에 적용된 조건에 따른다.
카카오 지도와 주소·장소 검색에는 카카오 JavaScript 키를 사용한다. 현재 위치 확인에는 브라우저의 Geolocation API와 Permissions API를 사용한다.

주요 데이터 항목
공통: 시설명, 시설 종류, 주소, 위도·경도, 기준 위치로부터의 직선거리
주차장: 주차장 구분·유형, 주차면수, 운영요일·시간, 요금정보, 결제방법, 관리기관, 전화번호, 장애인 주차구역 여부
휴지통: 휴지통 종류, 세부 설치 위치
공원: 공원 구분
금연구역: 금연구역 범위 및 원자료의 이용 관련 상세 정보
화장실: 원자료의 개방·관리 및 편의시설 정보
무료와이파이: 설치 장소, 주소, 제공기관 등
자전거보관소: 보관소명, 주소, 보관 가능 대수 등
상세 정보는 실제 데이터에 포함된 항목을 기준으로 표시한다. 데이터기준일 등 일반 이용에 불필요한 정보는 시설 상세 화면에서 제외한다.
주차장·휴지통·공원·금연구역의 갱신은 제공기관의 주기를 따르며, CSV 자료는 원본 파일을 교체한 뒤 지역 데이터를 다시 생성해 반영한다. 실시간 운영 상태를 제공하는 서비스는 아니다.

데이터 샘플 확인 결과
현재 프로젝트는 7개 카테고리의 데이터를 지도와 시설 목록에 연결한 상태이다. 검색 기준 위치의 반경 3km 안에 있는 시설을 거리순으로 정렬하여 최대 100곳 표시한다. CSV 인코딩과 좌표 유효성, 주변 데이터 필터링 등을 확인하는 검증 스크립트가 마련되어 있다.
좌표가 없는 자료는 지도 검색에서 제외하며, API 조회용 지역 코드가 원본 CSV에 없는 경우 해당 기관의 데이터가 조회에서 누락될 수 있다. 전체 시설의 완전한 수록이나 현장 정보의 실시간 일치를 보장하지 않는다.

3. 주요 기능 정의

핵심 기능 1 — 7종 시설 통합 지도
주차장, 휴지통, 공원, 화장실, 금연구역, 무료와이파이, 자전거보관소를 하나의 지도에 표시한다. 시설별 색상과 아이콘을 적용하고 전체 또는 개별 카테고리로 필터링한다.
마커가 밀집하면 같은 카테고리끼리 묶어 숫자로 표시한다. 카테고리가 다른 클러스터는 분리하고, 겹치는 표시 위치를 벌린다. 클러스터를 선택하면 해당 시설들의 실제 위치를 중심으로 확대한다.

핵심 기능 2 — 위치 선택과 주변 시설 탐색
페이지 진입 시 위치 권한을 확인한다. 이미 허용된 경우 현재 위치를 가져와 조회하고, 미허용 상태에서는 시설 조회를 대기하며 안내를 표시한다. 확인 버튼을 누르면 권한 요청을 시작하고, 차단된 상태에서는 브라우저 설정 변경 방법을 안내한다.
권한 없이도 위치 수정 창에서 주소·장소를 검색하거나 지도를 움직여 중앙 핀이 가리키는 위치를 선택할 수 있다. 해당 위치에서 검색 버튼을 누르면 내 위치 마커, 거리 기준과 시설 조회 위치가 함께 변경된다. 단순한 지도 이동이나 위치 수정 취소로는 거리 기준이 바뀌지 않는다.

핵심 기능 3 — 반응형 상세 정보와 길찾기
PC에서는 시설을 선택하면 목록의 해당 항목 아래로 상세 정보가 펼쳐진다. 지도 핀을 선택해도 해당 목록 항목으로 이동해 같은 상세 정보를 표시한다. 모바일에서는 목록 아코디언 대신 하단 바텀시트가 올라온다.
선택한 마커는 부드럽게 커지고 상세 정보를 닫으면 원래 크기로 돌아간다. 상세 하단의 카카오맵으로 길찾기 버튼은 현재 설정한 위치와 선택 시설을 출발지·도착지로 지정한 도보 길찾기로 연결한다.

사용자 시나리오
1. 사용자가 공공이 웹앱에 접속한다.
2. 위치 권한이 허용되어 있으면 현재 위치를 확인한다. 미허용이면 확인 버튼으로 허용을 요청하거나 위치 수정으로 원하는 위치를 직접 지정한다.
3. 선택한 위치의 반경 3km 안에 있는 시설이 지도와 거리순 목록에 표시된다.
4. 전체 또는 원하는 시설 카테고리를 선택한다.
5. 시설 목록이나 지도 핀을 눌러 시설을 선택한다. 필요한 경우 묶음 마커를 눌러 확대한다.
6. PC에서는 목록 아코디언, 모바일에서는 바텀시트로 주소와 이용 정보를 확인한다.
7. 카카오맵으로 길찾기를 눌러 설정한 내 위치에서 시설까지의 도보 경로를 확인한다.
8. 다른 지역을 탐색하려면 위치 수정 창에서 새 위치를 확정한다.

4. 생성형 AI 활용 계획

활용 지점
현재 완성본에는 사용자에게 제공하는 AI 요약·추천 화면이나 생성형 AI API 연동이 없다. 생성형 AI는 개발 과정에서 화면 구성, 코드 작성, 데이터 처리 방식 개선, 오류 원인 분석과 문서 정리를 돕는 용도로 활용하였다.
초기 기획의 서비스 내 AI 요약·추천은 향후 확장 항목으로 남겨두었다.

활용 목적
지도, 시설 목록, 위치 선택, 상세 정보 등 여러 UI의 상호작용을 정리하고, 반복적인 구현 작업과 버그 수정의 효율을 높이기 위해 활용하였다. 최종 기능과 출력 데이터는 실제 코드와 공공데이터를 기준으로 확인한다.

사용할 AI 종류 / API
개발 보조 도구: Codex
현재 서비스 실행 중 호출하는 생성형 AI API: 없음
향후 사용자용 AI 기능을 추가할 경우 모델·API 선정과 별도 서버 구성을 검토한다.

입력값 (Input)
개발할 기능의 요구사항, 현재 소스코드, 오류 상황, 화면 참고 이미지, 데이터 필드 구조 등을 개발 보조 도구에 제공한다. 현재 서비스에서 시설 검색 결과를 AI API로 자동 전송하는 흐름은 구현하지 않았다.

출력값 (Output)
개발용 코드 변경안, UI 구성안, 오류 수정안, 검증 코드와 문서 초안을 얻고 검토하여 프로젝트에 반영한다. 사용자 화면에는 AI가 생성한 시설 추천 문장 대신 공공데이터의 시설 정보를 표시한다.

예시 프롬프트 초안
예시 1: “시설을 선택하면 PC에서는 해당 목록 항목의 아코디언만 펼치고, 768px 이하 모바일에서는 하단 바텀시트만 표시하도록 수정해줘.”
예시 2: “카테고리별 클러스터를 분리하고, 색상과 개수를 유지하면서 겹치는 클러스터의 표시 위치를 벌려줘. 확대 기준은 실제 시설 위치를 유지해줘.”

실패/예외 처리 계획
AI가 제안한 코드는 실제 데이터 흐름과 기존 기능에 맞는지 검토한 뒤 적용한다. 린트와 기능별 검증 스크립트로 확인하고, 외부 지도 연결 및 모바일 화면은 실제 브라우저 점검을 병행한다. 구현하지 않은 기능이나 확인하지 않은 배포 상태를 완료로 기록하지 않는다.
현재 서비스는 생성형 AI API에 의존하지 않으므로 AI API 장애가 시설 조회에 영향을 주지 않는다. 향후 AI 요약을 추가할 경우 실패 시에도 기존 지도·목록을 유지하고, 제공된 시설 정보 외의 추측을 제한하는 방식을 검토한다.

5. 화면 설계

화면 목록 및 구성
① 메인 화면
서비스 이름과 소개 문구가 있는 상단 배너, 전체·7종 시설 카테고리 탭, 주변 시설 목록, 카카오 지도, 위치 수정 버튼, 내 위치로 이동 버튼, 데이터 출처 및 저작권 영역으로 구성한다. 별도의 상단 검색창은 두지 않고 주소·장소 검색을 위치 수정 창에 배치한다.

② 위치 수정 팝업
배경을 어둡게 처리한 중앙 팝업에 주소·장소 검색창, 지도, 화면 중앙에 고정된 핀, 해당 위치에서 검색 버튼을 배치한다. 사용자가 지도를 움직이면 중앙 핀이 가리키는 위치가 선택 대상이 된다. 확정하기 전까지 기존 조회 기준은 유지한다.

③ 시설 상세 정보
시설명, 주소, 직선거리와 시설별 필요한 정보를 표시하고 하단에 길찾기 버튼을 둔다. PC에서는 목록 안의 아코디언, 모바일에서는 화면 하단의 바텀시트로 제공한다. 두 상세 UI를 동시에 표시하지 않는다.

④ 위치 권한 안내
권한이 필요하거나 차단된 경우 오른쪽 상단에 안내 배너를 표시한다. 확인 또는 위치 수정으로 다음 행동을 선택할 수 있다. 모바일에서도 화면 너비 안에서 줄바꿈한다.

사용한 AI 도구 / 프롬프트
도구: Codex
화면 구성, 반응형 스타일과 상호작용 구현을 보조하는 데 활용하였다.
예시 프롬프트: “공공시설 지도 웹앱의 상단을 연한 초록색 계열로 정리하고 시설별 필터와 지도·목록이 잘 보이게 디자인해줘. 검색창은 위치 수정 팝업에 유지하고 모바일에서 가로 스크롤이 생기지 않도록 해줘.”

와이어프레임 / 스케치 삽입란
PC: 상단 소개 영역 → 카테고리 탭 → 시설 목록과 지도 → 데이터 출처 및 저작권
모바일: 상단 소개 영역 → 줄바꿈되는 카테고리 탭 → 지도·목록 세로 배치 → 시설 선택 시 하단 바텀시트
위치 수정: 검색창 → 중앙 고정 핀이 있는 지도 → 해당 위치에서 검색 버튼
제출 문서에는 현재 메인 화면, 위치 수정 창, 모바일 상세 바텀시트의 실제 화면을 각각 삽입한다.

화면별 주요 요소
메인: 지도, 색상·아이콘 마커, 카테고리별 클러스터
검색 결과: 직선거리순 시설 목록과 카테고리 필터
PC 상세: 목록 안에서 펼쳐지는 시설 정보
모바일 상세: 슬라이드 애니메이션이 적용된 바텀시트
위치 수정: 주소·장소 검색과 고정 핀 지도
출처 영역: 제공기관, 원본 링크, 이용조건 및 학습 목적 안내

6. 기술 스택 및 배포 계획

프론트엔드 / 백엔드 기술
프론트엔드: React 19, Vite 8, JavaScript, CSS
지도·검색: Kakao Maps JavaScript SDK와 장소·주소 검색 기능
위치: 브라우저 Geolocation API, Permissions API
공공데이터: 공공데이터포털 REST API와 CSV 파일데이터
전처리·검증: Node.js 스크립트, Oxlint
백엔드: 현재 별도 서버 또는 서버리스 함수 없음
사용자용 생성형 AI API: 현재 미연동

선택 이유
React로 지도, 시설 목록, 상세 화면과 위치 수정 팝업을 컴포넌트로 나누고 상태를 연동하였다. Vite로 개발 서버와 정적 빌드를 구성하였다. 카카오 지도 기능을 활용해 위치 표시, 검색과 카테고리별 클러스터를 구현하였다.
대용량 CSV는 개발·빌드 단계에서 지역별 JSON으로 나누어 브라우저의 초기 다운로드와 파싱 부담을 줄였다. 공공 API는 주변 지역만 요청하고, 캐시 재사용과 요청 취소로 불필요한 조회를 줄였다.
현재 API 요청은 클라이언트에서 실행한다. VITE_ 환경변수는 브라우저 번들에 포함되므로 서버에서 인증키를 숨기는 구조와는 다르다. 별도의 비밀키 보호가 필요한 기능을 추가할 때에는 백엔드나 서버리스 구성을 검토한다.

배포 방식
배포 예정 플랫폼은 기존 계획대로 Vercel을 우선 검토한다. 현재 앱은 Vite 정적 빌드 결과인 dist 폴더를 배포하는 구조이다. 배포 환경에 인증키와 원본 데이터를 준비하고, 카카오 개발자 설정에 실제 서비스 도메인을 등록해야 한다.
현재 프로젝트 파일만으로 실제 배포 완료 여부와 서비스 URL은 확인되지 않았다. 배포 완료 후 URL을 기록하고, 외부 환경에서 위치 권한·시설 조회·길찾기·모바일 화면을 점검한다.

7. 진행 일정 (3차시)

1차시 — 주제 선정과 데이터 구조 확인
주변 공공시설 탐색을 주제로 선정하고 공공데이터포털 API, CSV 자료와 카카오 지도 연동 구조를 확인한다. 초기 기획서와 화면 구성을 작성한다.

2차시 — 핵심 기능 구현과 사용성 개선
7종 시설 조회, 지역별 데이터 전처리, 카테고리 필터, 거리순 목록, 위치 수정, 카테고리별 클러스터를 구현한다. PC 아코디언·모바일 바텀시트, 선택 애니메이션, 길찾기, 위치 권한 안내와 출처 표기를 연결한다. 생성형 AI는 개발 보조에 활용하며 서비스 내 AI 추천은 구현 범위에서 제외한다.

3차시 — 최종 점검과 발표 준비
현재 구현 내용을 기획서와 README에 반영하고 기능별 검증을 수행한다. 실제 PC·모바일 환경의 권한 요청, 마커 선택, 팝업, 외부 길찾기를 확인한다. 배포를 완료하고 URL로 접속 가능한지 검증한 뒤 지도 탐색부터 길찾기까지 시연한다.

현재 상태
핵심 화면과 기능은 코드에 구현되어 있다. 실제 배포 URL 확인과 모바일 실기기 전 과정 점검은 최종 확인 항목으로 남아 있다.

8. 기대 효과 및 차별점

기존 유사 서비스 대비 차별점
서로 다른 출처의 7가지 공공시설 정보를 하나의 지도와 목록에서 탐색할 수 있다. 시설별 색상·아이콘과 카테고리별 클러스터를 사용해 여러 종류의 시설을 구분한다. 위치 권한을 허용하지 않아도 검색과 지도 드래그로 기준 위치를 직접 정할 수 있다.
PC에서는 목록 안의 상세 정보, 모바일에서는 바텀시트를 사용해 기기별 이용 흐름을 맞췄다. 시설 선택 이후 길찾기까지 연결하며, 주변 데이터만 불러오는 방식으로 대용량 자료의 처리 부담을 줄였다.

이 앱이 주는 가치 / 기대 효과
시설 종류마다 여러 사이트를 검색하는 번거로움을 줄이고, 필요한 생활시설의 위치와 이용 정보를 한 화면에서 비교할 수 있게 한다. 현재 위치뿐 아니라 방문 예정 지역의 시설도 미리 탐색할 수 있어 일상 이동과 지역 이용에 도움을 준다.
공공데이터를 실제 생활에서 활용할 수 있는 형태로 제공하고, 원본 출처와 제공기관을 명시하여 정보의 근거를 확인할 수 있게 한다. 목록의 거리는 직선거리이고, 운영정보·수용량은 원자료 기준이라는 한계를 구분해 안내한다.
